## OpenStreetMap objects, details and changes

### Objects (POIs)

- Access: type the kind of place into the search box
- URL path: `/#objects=<type>;<type>`

Not a tool that is opened: the POI types are a filter, and switching one on is what brings everything else with it. From two characters on, the search box lists the matching types under an **Objects (POIs)** caption, above the places it finds — each a checkbox, so picking one leaves the query and the list alone and several can be switched on in a row. A type is found by its name or by its raw tags (`amenity=pub`); the rows keep the order the match scored them in, so switching one on never moves another. A type already on is ticked, and switching it off is done from the same row, or from the chips in a selected object's details panel. Offline the section is empty: the objects are fetched. Matching types are visible interactively as markers with icons on the map; the objects come from Freemap's own OpenStreetMap query API, which holds Europe only.

While any type is on, a short **Objects (POIs)** toolbar stands for the filter — it has no open or close of its own, and the **×** that clears the filter is what takes it off the screen (<kbd>Del</kbd> does the same while nothing is selected). Its **⋮** menu carries **Marker style**, below a divider: a modal to set the marker shape (pin/ring/square) and color, applied to all displayed objects, and **Show label** (Always, On hover — the default, When selected, On hover or selected) for the objects' name tooltips, with **Show label always from zoom** (Never — the default, or a zoom from 8 up to the map's maximum zoom) showing them all from that zoom on. The shape and color can also be preset via the read-only `/#objects-style=` URL param (see `doc/url-params.md`).
While objects are displayed, that same **⋮ menu** offers **Convert all to drawing** and **Show all as Lookup**. Either hands the objects over for good: the type filter is cleared — which is also what takes the toolbar away — so they leave the map as objects (as lookups they arrive kept, and the element behind one is fetched from OSM only when it is clicked; at most 500 can be handed over at once, since each is named separately in the URL). A selected object's panel (see below) carries the same ⋮ menu for that one object, leaving the others alone — and leaving the object itself on the map, which is why it says **Copy to drawing** instead. For a way or a relation the conversion dialog offers the element's **own geometry** in place of the point it is drawn at; picking it fetches the element from OSM straight away, and if it turns out detailed enough to be worth thinning the dialog's own deviation slider appears, derived from it. That menu also carries the map context menu's whole list for where the object stands, and what can be done with the one object elsewhere: OpenStreetMap.org and its history, the two editors opened on the element itself, and the "Open in external application" targets. **Show as Lookup** on one object leaves it kept, the same way the whole screenful arrives kept. A type the object is in the way under is switched off in the details panel, where every kind of the object is a chip that toggles its type on or off (filled while the type is on, and a broader type showing the object gets a chip of its own even where the object's name doesn't mention it). <kbd>Del</kbd> clears the type filter while nothing is selected.

### Map details

- Access: Main menu > Map details
- Keyboard shortcut: <kbd>g</kbd> <kbd>i</kbd>
- URL path: `/#tools=map-details`

Toggles the map details toolbar. Clicking a location queries information about it, grouped by source (each toggleable via the **Sources** dropdown); the results are listed in the search box's dropdown and are displayed the same way search results are — the picked one for as long as it is selected, plus any kept through the **Keep on the map** button in its panel:

- **Reverse geocoding** — the locality / address of the point
- **Nearby** — features near the clicked point
- **Containing features** — administrative and geographic areas containing the point (cadastral community, district, region, mountain range, country, etc.)

The last two read OpenStreetMap data from Freemap's own query API, which holds Europe only; outside Europe they answer with nothing.

Selecting a feature opens a detail popup headed by its name and what kind of thing it is — each kind a chip that, where it matches a POI type, switches that category on or off, as the outdoor map legend's chips do — with the terrain-model elevation at it (read from the elevation API at one point of the feature — a line at its midpoint, anything else at the centre of its geometry — naming the model behind the number and offering premium a higher-precision one; a feature reaching more than 200 m across gets none at all, one reading saying nothing about a street, a railway route or a whole forest), its OSM tags, and the data source — for an OSM element a link opening it on osm.org. A feature tagged `wikidata`, `wikipedia`, `wikimedia_commons` or `image` also gets a carousel of Wikimedia Commons photos above its tags (the files and category those tags and its Wikidata item, or the item of its `wikipedia` article, name), one at a time with its description's first sentence and an n / total counter over it, each opening its Commons page, and under it a credit — **Wikimedia Commons**, the shown photo's author and its license; below the tags, the History button and the source, a table of its Wikidata facts in the UI language — a chosen set (population, area, elevation, height, prominence, length, depth, source and mouth of a river, discharge, dates founded, opened and demolished, heritage status, architect, style, religion, operator, owner, track gauge, IUCN category, website…), with **Show more** for every other statement but external identifiers, and **Source: Wikidata**; and a **Wikipedia** section titled with the article (in the UI language where Wikidata knows a version in it, else tagged with its language code), showing its opening with **Show more** for the rest of its text, and **Source: Wikipedia · CC BY-SA 4.0**. For an OSM element, a **History** button turns the popup to its versions, newest first, each with its date, author and changeset comment, under a breadcrumb back to the details; the versions are a step of their own in the browser history (`panel=…/history`), so Back returns to the details. The comment inspects that changeset as described under Map changes, without opening the Map changes tool, with the element selected in it as a click on the map would: the changeset's panel takes over, showing what changed on the element, its breadcrumb reaching back to the changeset, the history and the details (the last two select the element again, bringing its popup back); <kbd>Esc</kbd> steps back up a level. In an embed the comment links to the changeset on osm.org instead. For a peak, volcano, saddle or mountain pass node, the line is **Summit elevation** or **Saddle elevation** instead: read by the terrain service at the highest ground (or the saddle point) near the node, since OSM nodes are often a little off it, with no premium offer. Where that point lies 3 m or more from the node, a line under it says how far it is from the marker, with a map-marker toggle that marks it on the map wherever the service gives its position (a summit found on the national terrain model). Where the service has no value, the line stays **Elevation**, read at the marker. For a peak or volcano node the popup adds what the terrain service measured from the terrain models: its **prominence**, its **key col** (its elevation, and the name of the OSM saddle there if there is one; a map-marker toggle beside it marks the col on the map and moves the map to it, and while it is on a ⋮ menu copies the col as a point to Drawing and data), its **isolation**, and a **Show route to higher ground** toggle that draws the way from the summit over the key col to the first higher ground. Once drawn, a ⋮ menu beside the toggle copies the route to Drawing and data. The mark and the route go again when the selection changes. One ⓘ, on a bracket beside them, credits the terrain models behind those values. For a saddle or mountain pass node it adds the **saddle depth** and, where it applies, the peak it is the **key col of**, with a map-marker icon that selects that peak, both under one ⓘ. The popup is a panel docked over the map — on the right, or over the lower half of a phone's screen, where dragging its header shrinks it to the header or stretches it to the whole screen — headed **Object (POI)** or **Lookup** (minimized, by the feature's name — else its kinds, else its type and id — with its type icons beside it and its kinds and elevation on a line under it), holding the feature's actions in a row above the details (a search result's **Keep on the map** or, once kept, its delete button; the ⋮ menu; and the **Open in…** list as a menu button of its own) in place of a selection toolbar; selecting another feature swaps the panel's content, and its × or <kbd>Esc</kbd> deselects the feature. The **Actions** ⋮ menu (search results and objects alike) holds the map context menu's whole list for where the feature stands; the **Open in…** menu beside it holds the whole list of targets, each named for what it is rather than for the opening — "OpenStreetMap.org", "OpenStreetMap.org (history)", "JOSM" and "iD" all act on the element itself, which is why the list's own position-based editors are left out of it, and the other maps follow. The buttons' labels give way to their tooltips one at a time as the panel narrows. **Share location** sits with the rest of what acts on the place; copying the page URL is not offered here at all, being about the page rather than the feature — the main menu's **Share / Open in external app** is where that lives. It follows the selection and opens of itself for anything that is on the map because it was put there — an object, a map-details hit, an element asked for by id, a lookup that is kept. The one exception is a hit from searching by name that is merely being looked at: picking that is navigation, so it comes without the panel and with no toolbar (picking it again from the list doesn't open it); clicking it on the map does. In an embed every pick opens the panel, without the actions.

The geometry displayed for search and map-details results shares one style (color, fill, width, dash, line cap/join, marker shape — the same set as the track-viewer default style), editable in a dedicated **Lookup style** modal opened from the last row of the search box's dropdown (it carries a **Reset to default** button), which also sets **Show label** (Always, On hover — the default, When selected, On hover or selected) for the results' names, and **Show label always from zoom** (Never — the default, or a zoom from 8 up to the map's maximum zoom), from which they all show. The style can also be preset via the read-only `/#search-style=` URL param, and `window.fmHeadless.searchResultStyle` overrides it in headless image rendering (see `doc/url-params.md`).

### Map changes

- Access: Main menu > Map changes
- Keyboard shortcut: <kbd>g</kbd> <kbd>x</kbd>
- URL path: `/#tools=changesets`

Toggles the OSM changes toolbar, which contains: a dropdown to select the time window (changesets from the last 3, 7, 14, or 30 days), an "All authors" text input to filter by OSM username, a clear button, a button to download the changesets, and — once some have been found — a ⋮ menu that turns them into points of Drawing and data, taking them off the map and closing the toolbar.
OSM changes matching the selected parameters are displayed on the map as markers labelled with the mapper's name and changeset description — from zoom 14 always, below it while the marker or its row in the Map layers panel is hovered. Hovering a marker outlines the changeset's bounding box.

Clicking the marker (or the changeset's row in the Map layers panel) zooms the map to the changeset's bounding box, opens its panel (docked over the map like a selected object's, headed **Changeset** — minimized, **Changeset #<id>** with its author, date and comment on a line under it — with a book button for the Map changes chapter) with its author, description, date/time, its other tags (editor, imagery used, source, …; web addresses as links) and a link to it on osm.org, and inspects it the way OSMCha or Achavi does, from OSMCha's augmented diff. Where OSMCha has none (changesets before late November 2024, ones closed only minutes ago, and some it missed), the changes are rebuilt from the OSM API instead, and the panel says so: the untouched nodes of changed ways are then drawn where they are today, and ways whose only change was a moved node are not listed. While inspecting, the changeset markers are hidden (**Map brightness** in the Manage maps menu can dim the map layers so the changes stand out) and the Map changes toolbar, where open, is hidden until the inspection ends; an inspection needs no tool open, and one started otherwise (from an element's history or a link) leaves it closed. The panel's × ends it, and so does selecting anything with a panel of its own — a search result (opening an element as it is now included), an object, an OSM note or an event; starting an inspection deselects such a selection. A tool's own selection, such as a line being drawn or a route point, runs beside it. <kbd>Esc</kbd> steps back one level per press: it deselects the selected element, then closes an open drawing, route-planner or map-details tool, then ends the inspection. Inspecting a changeset, however it is started, takes the Map layers panel to a page listing its elements (picking a changeset under Map changes starts it too) (all but the untagged nodes of its ways, coloured by what happened to them); picking an element zooms to it and opens its details. The panel's Back returns to the list of changesets without ending the inspection. The changed ways and nodes are drawn in green (created), orange (modified) and red, dashed (deleted), with the previous geometry of anything that moved in dashed grey; untagged vertices of created ways are left out. The panel then shows the counts of created, modified and deleted elements and lists the changed relations, which are not drawn. Clicking an element or a listed relation highlights it and turns the panel to it: its versions, a before/after tag table (added, removed and changed tags highlighted), whether its geometry changed or only its nodes moved, added and removed relation members, and a link to its history on osm.org. That one panel drills from the changeset to one of its elements, with a breadcrumb on top leading back up, and no selection toolbar of its own; its × ends the inspection. The map zooms to the changes when they are off screen. The inspected changeset is in the URL as `panel=changeset/<id>`, and with an element of it selected as `panel=changeset/<id>/<type>/<id>`, so such a link opens the inspection directly, at that element, without the Map changes tool (older links' `changeset=<id>` still open it).

### OSM notes

The **OSM notes** overlay (`n`, <kbd>shift</kbd> <kbd>n</kbd>, from zoom 10) shows the open OpenStreetMap notes in the view as pins, loaded from the OSM API (at most 1000 per view), each labelled with its author and opening comment — from zoom 14 always, below it on hover, the selected one always; clicking one selects it (`panel=osm-note/<id>`) and shows its comment thread. In the **Map layers** panel its row counts the notes loaded and opens a page listing them, each by its opening comment's text, with its author, date and number of replies under it: a filter box from ten notes on finds them by any comment's text or author, and a sort, remembered, orders them newest, oldest, recently active (each row then dates its last activity) or most commented first. Tapping one selects it as its pin does. Zoomed out below 10 the list asks to zoom in; with 1000 notes it says the rest need a closer view.
