## Drawing and data

- Access: Main menu > Drawing and data
- Keyboard shortcut: <kbd>g</kbd> <kbd>g</kbd>; URL path: `/#tools=import-file` (the old `track-viewer` alias still works)
- Drawing modes, each opening the same toolbar with that mode picked:
  - <kbd>g</kbd> <kbd>p</kbd> for drawing points (markers) / measuring coordinates and elevation; URL path: `/#tools=draw-points`
  - <kbd>g</kbd> <kbd>l</kbd> for drawing lines / measuring distance and azimuth; URL path: `/#tools=draw-lines`
  - <kbd>g</kbd> <kbd>n</kbd> for drawing polygons / measuring area; URL path: `/#tools=draw-polygons`

Several tools can be open at once, each with its own toolbar, and the `tools=` URL parameter lists them (e.g. `/#tools=route-planner,tracking`; the older `tool=` spelling is read the same way). The exception is the tools that take clicks on the map — route finder, a drawing mode, map details: only one of those is open at a time, opening another replaces it, and while one is open a click no longer selects a feature. Its toolbar is outlined in green to say so. Escape closes it; the other toolbars are closed by their own button. Every toolbar below the logo — a tool's, the GPS recorder's, a layer's (photos, weather radar, viewshed, a connected map), the selected feature's, and the colorize legends — sits in the order it came up, so a new one joins the end instead of reshuffling the ones already there.

Everything drawn, imported from a file, copied from live tracking, or brought in from a search result, an object, a planned route or changesets is one collection of points, lines and polygons, edited with one toolbar.

**Where it is kept.** While the collection is small enough — up to about 8000 characters encoded, and holding nothing the link cannot spell (a per-point value that is text rather than a number) — it is written into the URL as `point=` / `line=` / `polygon=` params (see "Deep links" in [llms.txt](/llms.txt)), recorded elevation, times and numeric per-point values such as heart rate included, so the link shares it and Back/Forward step through its edits. A larger collection is kept in this browser instead (IndexedDB), each edit as its own snapshot named in the browser history, so Back/Forward step through it too; the toolbar then shows an **Unsaved** warning, since sharing the link would not share it — **Save to my maps** keeps it. The browser keeps the last hundred or so snapshots; going back to one it no longer holds says so and leaves the map empty. Data loaded by `track-uid=` or `import-url=` is imported: once it is here, the URL carries it (or a snapshot) like any other data, and the source param is dropped.

**The toolbar:**

- **Drawing mode** (dropdown) — Select (clicks select features), Point, Line, Polygon. A drawing mode takes map clicks: each click adds a point, or a vertex of the line or polygon being drawn; <kbd>Esc</kbd> or **Stop drawing** ends it.
- **Default style** (first in the ⋮ menu, which is always there; <kbd>e</kbd> <kbd>d</kbd>) — the style (color, fill color, width, line cap, line join, dash style, shape) given to new drawings and to imported features that carry no style of their own, plus **Show label** (Always — the default, On hover, When selected, On hover or selected), which decides when labels appear on the map. The style can also be preset via the read-only `/#track-style=` URL param (see `doc/url-params.md`). Hover labels appear only while features can be selected — not while a drawing or other map-click tool is active, nor in an embedded map.
- **Upload** opens the file import modal (URL path: `/#show=file-import`; legacy `/#show=upload-track` still works), which accepts GPX, KML, KMZ, TCX and GeoJSON files; several files can be picked or dropped at once and are merged into one view. Files can also be dropped anywhere on the map. When something is already on the map, importing asks whether to **append** the new data or **replace** it. An external file can also be loaded directly by URL via `/#import-url=<URL>` (legacy `gpx-url=` and `load=` still work).
- **Colorize by** (dropdown, while there are lines) — Inactive, then the modes in groups set off by dividers: Elevation, Steepness / Time, Speed, Expected speed, Heading / Surface, Smoothness, Road type, Track grade, Curviness, Speed limit, the two difficulty ratings and Waymark color (Expected speed and those from Surface on once the track has been matched to the path network) / Heart rate, Cadence, Power, Temperature / Battery, GSM signal (entries with no data in the track are disabled; every mode except Elevation, Speed and Time is premium — badged with a gem and disabled without premium access). While a mode is active, the dropdown's first item is a **Show colorizing legend** checkbox (set off by a divider) that toggles a color-scale legend below the toolbar; hovering over its scale, or touching and dragging along it, reads out the exact value at that point
- **More** (⋮ menu), besides Default style while something is on the map:
  - **Update elevation** — refill/override elevation from the terrain model (shown only while a track still has recorded elevation to replace); premium users get the high-resolution DEM where available
  - **Simplify all** — thins every line and polygon in place. The dialog's slider starts on a deviation derived from the data's own density and reads out how many points it would be left with; the per-point channels and the matched path details are thinned alongside the coordinates. A surviving point carries the **average** of the sensor samples it now stands for (heart rate, cadence, power, speed, temperature) rather than just its own, since the algorithm keeps corners and those correlate with slowing down; times and bearings keep their own point's value, and elevation rides along in the coordinate untouched. Shown only while something but points is on the map
  - **Save to my maps** — save the collection into a new personal map (requires login; prompts to log in first otherwise). Hidden when a map is already active, since the active-map toolbar's own **Save** persists it with the map. Older `#track-uid=…` share links still load
  - **Upload GPS trace to OpenStreetMap** — uploads the recorded tracks as GPX to the user's OpenStreetMap account as a GPS trace — only lines with recorded times, since OSM's import keeps nothing else — asking for a description (prefilled with the first such track's name), comma-separated tags and the OSM visibility (Identifiable — the default, Public, Trackable, Private; the last choice is remembered). The first upload asks permission through an OpenStreetMap authorization popup: a logged-out user logs in with OpenStreetMap, a user without OSM gets it connected to their account; opening the dialog checks the stored permission with OSM, so a revoked one is asked for again on Upload. The success message links to the trace's page on OSM. Shown only while a track with times is loaded; also opens via `#show=track-viewer-osm-upload`
  - **Bulk properties** — **All features**, **All points**, **All lines** and **All polygons**, each opening the Properties editor for those features at once (also under the collection's section of the Map layers panel). It works the way JOSM edits a multiple selection: a label, style field or property shared by all shows its value, and only what the user changes is written — to every feature — while everything left untouched stays each feature's own. One that differs shows `<different>` with a **Change** button, which brings up its control to set it on all (to an empty value too); **Keep** takes it back. A kept property row keeps each feature's value (renaming its key renames it on all), a deleted row is removed from all, and a new row is added to all. That is how one label template, such as `{p:name}[ ({p:ele} m)]`, is given to many features at once.
- a close button. There is no delete-all here, nor on <kbd>Del</kbd> with nothing selected; everything goes from the Map layers panel (the **Drawing and data** row's Remove) or the main menu's Clear map

**Measurement readouts:** drawing a line shows its length; a polygon shows its area and perimeter (each copyable). A point can show its coordinates and elevation; the gem beside the elevation names the terrain model it was read from, and for non-premium users offers higher-precision data.

**Selecting a feature.** Clicking a line, polygon or point on the map selects it and gives it a **selection toolbar** of its own, without opening the tool; data brought in by an import, a finished recording or a copy arrives with its line already selected where it holds exactly one. The selected feature is highlighted by a blue halo, and the toolbar is named by the feature's label — a line without one by its Kind, numbered among the lines of that kind ("Planned route 1", "Recorded track 2", "Line 3"), a point or polygon without one by what it is. A selected line is the one the elevation profile, "More info" and "Match to paths" act on. The 🗑 button (<kbd>Del</kbd>) deletes just that feature; the last one deleted clears the map. The toolbar offers **Properties** and, for a line (narrower screens fold the rarer buttons into the ⋮ menu):

- **Modify** — shows a handle on every vertex in view: drag one to move it, drag the midpoint between two to insert a vertex there, click one to select it. A vertex keeps its recorded values (elevation, time, heart rate…) when moved; an inserted one has none. Very long lines show handles only where few enough are in view.
- **Elevation profile** — see below
- **More info** — a popup with the track's distance, min/max elevation, total climb and total descent
- **Split** — cuts the line in two. Arming it makes the track offer the recorded point nearest the pointer as the cut, labelled with how far into the track it sits and how much of it is left past the cut, and the selection halo splits into two colours at it (blue up to the cut, amber past it); a mouse cuts where it points, a finger places the cut first (dragging it along the track to adjust) and confirms it from the toolbar. Arming it replaces the selection toolbar with a bar saying to click the track where to cut it and a Cancel button (<kbd>Esc</kbd> does the same); every other toolbar and floating window goes away while it is armed. The cut is always an existing point of the track, which both halves keep, and the per-point channels are cut alongside the coordinates
- **Split into segments** (the Split button's caret) — breaks a multi-segment recording (a segment per recorder pause) into a feature per segment; offered only for a line that has more than one
- **Join** — joins the selected line with another one: into one line, or keeping a segment each (drawn with a gap rather than a straight line across the break). Picking one arms the join: a bar says to click the line to join with, alongside a Cancel button (<kbd>Esc</kbd> does the same), and the next line clicked is joined onto the selected one, lighting up as it is pointed at. Recorded times decide which line comes first and are never made to run backwards; without them the pairing of endpoints with the smallest gap wins, so either line may be turned round. The per-point channels, the path details and the elevation credits of both come along, and the selected line's own name, style and metadata carry over to the result, its name with the other's appended. Offered only while there is more than one line
- **Match to paths** (⋮ menu) — snap the track onto GraphHopper's routing graph. It asks which transport carried it, since nothing in a GPX says. The matched line replaces the track and carries the path details the router valued it by, which is what makes Surface, Smoothness, Road type, Track grade and the difficulty ratings available for a recording; it also removes GPS wander. The matched line has its own points, so the track's timestamps and recorded sensor data are lost — the modal warns when the track actually has any. Each recorded segment is matched separately; a segment it cannot get through is left as recorded. It declines when the result comes back meaningfully longer than the recording, since that means it routed *around* where the track went. A track that changes transport partway has to be split first
- **Simplify**, **Reverse direction**, **Project point** and **Open in JOSM** (⋮ menu)

A polygon gets Modify, Simplify, Reverse direction, **Cut out a hole**, **Make a hole of the enclosing polygon** (when it lies inside another one) and Open in JOSM; a selected hole gets **Detach hole**. A point gets an ⋮ **Actions** menu (named only in its tooltip) — project a point, the map context menu's whole list for the point, and an **Open in…** submenu holding the new window and the external apps — and can be dragged to move it while it is selected.

**A selected vertex** gets a toolbar of its own: **Point data**, **Split** the line there, **Join** another line onto that end, **Continue** drawing from it, or delete it (<kbd>Del</kbd>). A polygon's vertex can be deleted. **Point data** opens a dialog with the vertex's latitude, longitude and elevation and, on a recorded track, its time and every per-point value the track carries (heart rate, cadence, power, temperature, speed in km/h, …), each editable; an empty field leaves the point without that value. Which values a line has is set in its Properties (see below), so a line drawn by hand, its **Kind** set to Recorded track and given a time and a heart rate there, can be filled in point by point, and colorize, the elevation profile and the GPX export then read it like a recording. The time is shown in the viewer's time zone and must lie between the neighbouring points' times.

**Open in JOSM** on a line, a ring or a hole hands the geometry itself to a running JOSM as a new layer of unsaved data (remote control, `load_data`), the ring closed so JOSM reads it as an area; a polygon that has holes goes as a multipolygon relation, its rings the outer and inner members. The feature's properties travel with it as tags — on the relation where there is one — plus its label as `name` where the label is written plainly. A **point** goes the other way — JOSM downloads 100 m around it and adds a node standing there, tagged the same way (a template label says something different wherever it is drawn, so it is never a name; the toposcope-centre marker property is not a tag either). iD is not offered for a drawing — it can be pointed at a place or an existing element, but has no way to be given geometry. A **photo**'s own menu works the same way as a point's: JOSM gets a node at the photo's position tagged `image=` with the address the "New window" item opens (the raw picture, or the Commons file page), the access token left off — and no `name`, a photo's title being what the picture is called rather than the feature.

**Holes in polygons.** A polygon can have holes (an island in a lake is just a further hole, since rings alternate filled/empty). **Cut out a hole** on a selected polygon switches to polygon drawing and turns the next ring drawn into a hole of it; a polygon drawn entirely inside another one instead offers **Make a hole of the enclosing polygon** (the smallest one containing it). A hole is fully subordinate — it has no label or style of its own, is drawn and measured as part of its parent (the area readout subtracts it, the perimeter counts its outline), is not clickable inside, and is deleted with it. **Detach hole** turns it back into a polygon of its own. In the URL a hole carries the extra style-field code `H` naming its parent polygon's position among the `line=`/`polygon=` params.

**Properties modal:** Label, Color, Shape, Icon (searchable picker), and Text (up to 2 characters shown inside the marker); lines/polygons additionally expose fill color, width, line cap/join and dash style, and a line whose ends meet can be switched between line and polygon. A line also has a **Kind** — Line, Recorded track or Planned route — read from the file it was imported from (a GPX `<trk>` or `<rte>`) and changeable here: a track or a route gets start and finish markers, and a route exports to GPX as `<rte>` and is never offered for upload to OpenStreetMap as a GPS trace. A track or a route then shows **Track details** (or **Route details**), its own GPX fields as named fields — Description, Comment, Activity type (any text, with common ones suggested), Source and Number — which travel to and from GPX as `<desc>`, `<cmt>`, `<type>`, `<src>` and `<number>`; on a plain line the same keys are ordinary rows of the properties table, and switching the Kind moves them between the two. Every point has **Waypoint details** the same way — Description, Comment, Type (common ones suggested), Time (in the viewer's time zone), Elevation and Source — written to GPX as the `<wpt>`'s own elements; GPX `<link>`s, on a track, a route or a waypoint alike, are a `links` row of the properties table holding a JSON list of `{href, text, type}`; the elevation is the point's coordinate, so this is where a single point's elevation is set by hand. Under it, **Per-point values** lists the line's per-point channels — time, heart rate, cadence and the rest — as chips, each with how many of its points have a value ("3 of 120 points") and an × that removes it from the whole line; clicking the input after them lists the known channels the line lacks (typing filters them), and picking one adds it, empty at every point until filled in through Point data. The label is a multi-line field — Enter starts a new line rather than saving, and the map draws the label over as many lines as it was written on, centred. The style is written into the feature's own properties, in our `freemap:*` form and in simplestyle alike, so it survives an export and reads back the same — and the feature then stops following the **Default style**.

**Properties.** Every point, line and polygon also carries a table of free-form key/value **properties**, edited in the same modal. Each row has a type, picked from a button beside its name — Text (`Aa`), Multi-line text (`¶`, edited in a box under the row), Number (`#`), `true`, `false`, `null` or JSON (any JSON value — an object, an array, or `"6"` for the string 6 — edited in a box under the row and checked as typed) — which is what a GeoJSON export writes; a row with a value but no name, a name another row has, or a Number or JSON value that doesn't read as one holds up saving (a row with neither name nor value is skipped); labels, OpenStreetMap tags and a GPX export's `<fm:prop>`s read the value as text and leave out nulls, objects and arrays — except that a GPX export writes a `links` list as `<link>`s. Editing many features at once keeps the rows as text, a number or boolean staying one while it still reads as one. Bringing in an object (POI) or a search result opens a **conversion dialog** that decides what comes along. It lists every property the features carry — with a count beside each when there are several, the most widespread first — and only `name` is ticked, since every carried property is written into the URL and a well-mapped POI has dozens — except for a file of ours, whose own property table and label template arrive whole, so reading one back stays lossless. The **Label** field starts as `{p:name}` and each row has a `{p:key}` button that writes its own token into it at the cursor, under it the same key hint the feature's own editor shows for that shape — it is the same label language, so a computed key such as `{location}` or `{area}` works here too; where the shape isn't known yet, as for an OSM way's own geometry, the hint keeps to what is certain. Left as it opens, every feature keeps the label the conversion would have given it, while anything typed there, a cleared field included, applies to all of them. A **Store label as** choice under the field — **Template** or **Plain text**, with a preview of the result beneath it — says what is stored: **Template** carries `{p:name}` as written, so the label keeps following the property; **Plain text** resolves it per feature at conversion. Under Template, a property the label uses is transferred whether or not it is ticked. Where the geometry is detailed enough to be worth thinning, the same dialog carries the simplification slider, and for a single OSM object it offers the element's own geometry instead of the point it is drawn at — choosing that fetches the element there and then. Writing `{p:name}` anywhere in a label draws the value of the property called `name`, so a label references its data rather than holding a copy of it: edit the property and every label built from it follows. The `p:` prefix is required — the bare namespace belongs to what the app computes, so a computed key added in a later version can never change what an already-shared label meant. Some keys are computed from the geometry rather than stored. A **point** has `{location}` — its own position, latitude over longitude, as a toposcope engraves it. A **line** has `{length}`, plus `{azimuth}` when it is a straight two-point line. A **polygon** has `{area}` and `{perimeter}` — `{length}` is the same number as the perimeter. Every unit the measurement readout can be clicked through is nameable too: `{length_*}` and `{perimeter_*}` take `km`, `m`, `mi`, `yd`, `ft`, `nmi`; `{area_*}` takes `m2`, `km2`, `a`, `ha`, `mi2`, `yd2`, `ft2`, `ac`. The bare `{length}` and `{area}` pick a metric unit by size — metres then kilometres, and square metres then hectares then square kilometres — so a shared label reads the same for everyone; a non-metric unit has to be named. The readout's own arithmetic is what computes them, so a polygon's label and the readout above it agree — holes included. Square brackets mark an optional part: `{p:name}[ ({p:ele} m)]` writes the parentheses only where there is an elevation to put in them. A bracket pair with no placeholder in it is plain text, and `\[` writes one literally. A key that answers to nothing stays on screen as written, so a typo — or a forgotten `p:` — is visible rather than silently blank. The hint under the label field lists the feature's property names, each clicked to write its `{p:key}` into the label at the cursor, and the computed keys named there are clickable in the same way. A label without placeholders stays plain text; turning a plain label into a template keeps the old text as a `name` row in the table, so `{p:name}` still reaches it. Properties travel in the URL (the `P` style field, and `Q` for the typed ones), are stored in saved maps, and export as GeoJSON `properties` or as one `<fm:prop key="…">` element per pair in GPX — every key, so a property the user invented survives a round trip. A GPX `<name>` holds the label already rendered, for the benefit of software that knows nothing of templates; the table and the raw `<fm:label>` beside it are what restore the feature on import.

**Project point modal:** create a point at a given Distance (m) and Azimuth (°) from the selected point.

**Simplify** opens the shared simplification dialog. Its slider sets the **maximum deviation** — how far a point may sit off the line drawn without it — from 0.1 m to 1 km, with the leftmost position meaning no simplification. It steps through preferred numbers — 0.1, 0.12, 0.15, 0.2, 0.25, 0.3, 0.4, 0.5, 0.6, 0.8 and the same ten again in each decade up to 1000 — so every setting is a round number about a quarter coarser than the one before it. The dialog reads out how many points the geometry has now and how many it would be left with. The tolerance is a real distance in both directions: longitude is scaled by the latitude before the Douglas–Peucker pass, so the same setting thins an east–west line and a north–south one alike. Wherever else the app offers to simplify — bringing in a route, an OSM relation or a search result — it is this same slider, started on a deviation derived from the geometry's own density.

**Elevation profile** opens a chart of elevation along a line, with total climb and total descent; a line that carries no elevation of its own is sampled from the terrain model. Whatever the line is colorized by on the map colors the chart too — the area under the profile carries the palette and the outline goes neutral; the mode comes from the feature the chart is aimed at (the route finder's, this tool's or tracking's own **Colorize by**), and its legend names the scale for both. The marker that follows the pointer along the line adds what the line is colorized by at that place to its distance, elevation and climb readout. The values are smoothed against the chart's own scale the way the map's are against its zoom, so zooming into a stretch brings out detail the whole-track view averages away. Points are marked with their name and elevation, and their distance is ticked on the x-axis. Pointing at the chart marks the matching place on the map, labelled with its distance, elevation, climb/descent so far, and the local steepness in both percent and degrees (signed: positive climbs in the direction of travel); pointing at the charted line on the map does the same the other way round. The distance axis zooms — the mouse wheel over the chart, or a two-finger pinch — and once zoomed, dragging the plot slides that window along the profile, with a thin bar above the plot showing which part of it is on screen. The elevation axis keeps the whole profile's range whatever is zoomed into. Shift-dragging across the plot (or a long press then a drag, on a touch screen) marks out a **stretch** of the profile: it is banded in the chart, highlighted on the map, and the footer swaps the whole line's climb totals for that stretch's own figures — its length, its climb and descent, the elevations it runs between, and its end-to-end steepness. Either edge can be dragged afterwards by the handle on it, and dragging one past the other turns the stretch round; the × beside the figures clears it. A one-off toast names the chart's three gestures, worded for a mouse or for a touch screen, with the usual "Don't show next time". It rides in the URL as `elevation-chart-range=<from>,<to>` (metres along the profile). Pressing a place in the chart brings it out on the map: unless it is already well in view, the map moves so the place sits in the middle of its largest part that nothing covers. Dragging along the chart (unzoomed) then keeps the marked place still on screen and slides the map under it. A toolbar below the chart can download it as SVG (not in an embedded map, where the browser forbids downloads), open the elevation preferences, put the panel full screen, and, when the line carries points, toggle their markers and labels; the grips at its corners move and resize the chart window, and both the size and the position are remembered. Under the toolbar the chart credits the terrain models its elevation was actually read from, as the elevation API reports them: the national high-resolution ones (premium) plus GEDTM30 past their borders, or SRTM. Past two credited agencies the footer shows the label with their count, which opens the whole list in a toast — the elevation readout's ⓘ does the same. A route on the free tier keeps the router's own elevation instead, which is credited to Sonny's LiDAR DTM. Non-premium users get a premium gem there offering higher-precision data. Elevation the user recorded or imported is credited to nobody.

Only one profile is shown at a time, and it stays with whatever opened it — a planned route, a line of this tool or a tracked device — redrawing itself as that line changes rather than closing. Closing the tool it was opened from does not close it either. It goes when its own × is pressed, when the map is cleared, or when the line it charts is deleted. Which one it is shows in the URL as `elevation-chart=` (see "Deep links" in [llms.txt](/llms.txt)).
