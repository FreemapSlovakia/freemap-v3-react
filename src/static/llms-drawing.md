## Drawing and measurement

- Access: Main menu > Drawing and measurement
- Keyboard shortcut:
  - <kbd>g</kbd> <kbd>p</kbd> for drawing points (markers) / measuring coordinates and elevation; URL path: `/#tools=draw-points`
  - <kbd>g</kbd> <kbd>l</kbd> for drawing lines / measuring distance and azimuth; URL path: `/#tools=draw-lines`
  - <kbd>g</kbd> <kbd>n</kbd> for drawing polygons / measuring area; URL path: `/#tools=draw-polygons`

Several tools can be open at once, each with its own toolbar, and the `tools=` URL parameter lists them (e.g. `/#tools=route-planner,tracking`; the older `tool=` spelling is read the same way). The exception is the tools that take clicks on the map — route finder, drawing, map details: only one of those is open at a time, opening another replaces it, and while one is open a click no longer selects a feature. Its toolbar is outlined in green to say so. Escape closes it; the other toolbars are closed by their own button. Every toolbar below the logo — a tool's, the GPS recorder's, a layer's (photos, weather radar, viewshed, a connected map), the selected feature's, and the colorize legends — sits in the order it came up, so a new one joins the end instead of reshuffling the ones already there.

Toggles the drawing and measurement toolbar. The toolbar lets the user switch between Point / Line / Polygon and open **Style settings** (<kbd>e</kbd> <kbd>d</kbd>), the default drawing style (color, fill color, width, line cap, line join, dash style, shape) applied to new drawings, plus **Show label** (Always — the default, On hover, When selected, On hover or selected), which decides when the labels of all drawn features appear on the map. Hover labels (here and in the Marker style, Default style and Lookup style modals) appear only while features can be selected — not while a drawing or other map-click tool is active, nor in an embedded map.

**Measurement readouts:** drawing a line shows its length; a polygon shows its area and perimeter (each copyable). A point can show its coordinates and elevation; the gem beside the elevation names the terrain model it was read from, and for non-premium users offers higher-precision data.

**Editing a selected geometry** — a context toolbar offers **Properties** plus, via a "⋮" menu:

- Lines: Elevation profile, Project point, Simplify, Reverse direction, Convert to Tracks and data, Open in JOSM
- Polygons: Cut out a hole, Simplify, Reverse direction, Convert to Tracks and data, Open in JOSM
- Polygon holes: Detach hole, Simplify, Reverse direction, Open in JOSM (a hole is part of its parent shape, so converting to Tracks and data is offered on the parent)
- Points: an ⋮ **Actions** menu (named only in its tooltip) — project a point, convert it to Tracks and data, the map context menu's whole list for the point, and an **Open in…** submenu holding the new window and the external apps

**Convert to Tracks and data** hands the selected feature to the track viewer as ordinary loaded data, asking first whether to append to or replace what it already holds, and opens that toolbar. It is written the way the data export writes it — the same styles and the same lossless `freemap:*` shadows — so it reads back as it went in. The feature goes with it: a drawn one is deleted (a polygon taking its holes), a lookup result comes off the map, a planned route and a screenful of changesets are deleted and their toolbars close, and every visible object is handed over with the type filter that fetched them, taking the objects toolbar too. The exception is **one** object, which is copied — objects are live data, refetched on every pan, so a single one cannot be taken away; that item says "Copy" instead. The same item sits on the lookup and object selection menus; for a single object the dialog also offers the element's **own geometry**, which fetches the way or relation from OSM first.

**Open in JOSM** on a line, a ring or a hole hands the geometry itself to a running JOSM as a new layer of unsaved data (remote control, `load_data`), the ring closed so JOSM reads it as an area; a polygon that has holes goes as a multipolygon relation, its rings the outer and inner members. The feature's properties travel with it as tags — on the relation where there is one — plus its label as `name` where the label is written plainly. A **point** goes the other way — JOSM downloads 100 m around it and adds a node standing there, tagged the same way (a template label says something different wherever it is drawn, so it is never a name; the toposcope-centre marker property is not a tag either). iD is not offered for a drawing — it can be pointed at a place or an existing element, but has no way to be given geometry. A **photo**'s own menu works the same way as a point's: JOSM gets a node at the photo's position tagged `image=` with the address the "New window" item opens (the raw picture, or the Commons file page), the access token left off — and no `name`, a photo's title being what the picture is called rather than the feature.

While drawing, individual nodes can be edited: a line point can **Join** another line, **Continue** drawing, **Split** the line, or be deleted; a polygon point can be deleted. Join waits for the point to join to: every other toolbar and floating window goes away, leaving a bar that says so and cancels (<kbd>Esc</kbd> does the same) — the same bar the geodata viewer's own join and split put up.

**Holes in polygons.** A polygon can have holes (an island in a lake is just a further hole, since rings alternate filled/empty). **Cut out a hole** on a selected polygon switches to polygon drawing and turns the next ring drawn into a hole of it; a polygon drawn entirely inside another one instead offers **Make a hole of the enclosing polygon** (the smallest one containing it). A hole is fully subordinate — it has no label or style of its own, is drawn and measured as part of its parent (the area readout subtracts it, the perimeter counts its outline), is not clickable inside, and is deleted with it. **Detach hole** turns it back into a polygon of its own. In the URL a hole carries the extra style-field code `H` naming its parent polygon's position among the `line=`/`polygon=` params.

**Properties modal:** Label, Color, Shape, Icon (searchable picker), and Text (up to 2 characters shown inside the marker); lines/polygons additionally expose fill color, width, line cap/join and dash style. The label is a multi-line field — Enter starts a new line rather than saving, and the map draws the label over as many lines as it was written on, centred.

**Properties.** Every point, line and polygon also carries a table of free-form key/value **properties**, edited in the same modal. Converting an object (POI), a search result or loaded data into a drawing opens a **conversion dialog** that decides what comes along. It lists every property the features carry — with a count beside each when there are several, the most widespread first — and only `name` is ticked, since every carried property is written into the URL behind the drawing and a well-mapped POI has dozens — except for a file of ours, whose own property table and label template arrive whole, so reading one back stays lossless. The **Label** field starts as `{p:name}` and each row has a `{p:key}` button that writes its own token into it at the cursor, under it the same key hint the drawing's own editor shows for that shape — it is the same label language, so a computed key such as `{location}` or `{area}` works here too and is left for the drawing to answer; where the shape isn't known yet, as for an OSM way's own geometry, the hint keeps to what is certain. Left as it opens, every feature keeps the label the conversion would have given it — one field cannot say that for a batch whose features each have their own — while anything typed there, a cleared field included, applies to all of them. A **Store label as** choice under the field — **Template** or **Plain text**, with a preview of the result beneath it — says what is stored: **Template** carries `{p:name}` as written, so the label keeps following the property; **Plain text** resolves it per feature at conversion, so a point can be named without carrying the property it was named from. Under Template, a property the label uses is transferred whether or not it is ticked, since an unanswered `{p:name}` would draw nothing. Where the geometry is detailed enough to be worth thinning, the same dialog carries the simplification slider, and for a single OSM object it offers the element's own geometry instead of the point it is drawn at — choosing that fetches the element there and then, so its shape decides the key hint and its detail the slider, and the conversion neither fetches it again nor asks a second question. Writing `{p:name}` anywhere in a label draws the value of the property called `name`, so a label references its data rather than holding a copy of it: edit the property and every label built from it follows. The `p:` prefix is required — the bare namespace belongs to what the app computes, so a computed key added in a later version can never change what an already-shared label meant. Some keys are computed from the geometry rather than stored. A **point** has `{location}` — its own position, latitude over longitude, as a toposcope engraves it. A **line** has `{length}`, plus `{azimuth}` when it is a straight two-point line. A **polygon** has `{area}` and `{perimeter}` — `{length}` is the same number as the perimeter. Every unit the measurement readout can be clicked through is nameable too: `{length_*}` and `{perimeter_*}` take `km`, `m`, `mi`, `yd`, `ft`, `nmi`; `{area_*}` takes `m2`, `km2`, `a`, `ha`, `mi2`, `yd2`, `ft2`, `ac`. The bare `{length}` and `{area}` pick a metric unit by size — metres then kilometres, and square metres then hectares then square kilometres — so a shared label reads the same for everyone; a non-metric unit has to be named. The readout's own arithmetic is what computes them, so a polygon's label and the readout above it agree — holes included, which come off the area and count towards the perimeter. Square brackets mark an optional part: `{p:name}[ ({p:ele} m)]` writes the parentheses only where there is an elevation to put in them, which is how a label that lists several facts survives one of them being absent — punctuation cannot be guessed at, since a joiner and a caption look alike. A bracket pair with no placeholder in it is plain text, and `\[` writes one literally. The hint under the Label field lists whichever set applies to what is selected. A key that answers to nothing stays on screen as written, so a typo — or a forgotten `p:` — is visible rather than silently blank. Each row in the table has a button that writes its `{p:key}` into the label at the cursor, and the computed keys named in the hint under the field are clickable in the same way — which is how the placeholders are found without knowing the syntax. The hint's own `{p:name}` example is not: it names a property the feature may not have, and the ones it does have are in the table. Properties travel in the URL (the `P` style field), are stored in saved maps, and export as GeoJSON `properties` or as one `<fm:prop key="…">` element per pair in GPX — every key, so a property the user invented survives a round trip. A GPX `<name>` holds the label already rendered, for the benefit of software that knows nothing of templates; the table and the raw `<fm:label>` beside it are what restore the drawing on import.

**Project point modal:** create a point at a given Distance (m) and Azimuth (°) from the selected point.

**Simplify** opens the shared simplification dialog. Its slider sets the **maximum deviation** — how far a point may sit off the line drawn without it — from 0.1 m to 1 km, with the leftmost position meaning no simplification. It steps through preferred numbers — 0.1, 0.12, 0.15, 0.2, 0.25, 0.3, 0.4, 0.5, 0.6, 0.8 and the same ten again in each decade up to 1000 — so every setting is a round number about a quarter coarser than the one before it, never a 0.19 next to a 0.21. The dialog reads out how many points the geometry has now and how many it would be left with. The tolerance is a real distance in both directions: longitude is scaled by the latitude before the Douglas–Peucker pass, so the same setting thins an east–west line and a north–south one alike, anywhere on the map. Wherever else the app offers to simplify — converting a route, an OSM relation, a recording, a track or a search result into a drawing — it is this same slider, started on a deviation derived from the geometry's own density, on its own for a route or an OSM relation and inside the conversion dialog for the rest.

**Elevation profile** opens a chart of elevation along a line, with total climb and total descent. Whatever the line is colorized by on the map colors the chart too — the area under the profile carries the palette and the outline goes neutral, so the two views of one line never say different things; the mode comes from the feature the chart is aimed at (the route finder's, the track viewer's or tracking's own **Colorize by**), and its legend names the scale for both. The values are smoothed against the chart's own scale the way the map's are against its zoom, so zooming into a stretch brings out detail the whole-track view averages away — the legend's own end labels are read at the map's zoom, so a zoomed-in chart can reach colors past what they name. Waypoints are marked with their name and elevation, and their distance is ticked on the x-axis. Pointing at the chart marks the matching place on the map, labelled with its distance, elevation, climb/descent so far, and the local steepness in both percent and degrees (signed: positive climbs in the direction of travel); pointing at the charted line on the map does the same the other way round, marking the place and its position in the chart. The distance axis zooms — the mouse wheel over the chart, or a two-finger pinch, about whatever is under it — and once zoomed, dragging the plot slides that window along the profile, with a thin bar above the plot showing which part of it is on screen. The elevation axis keeps the whole profile's range whatever is zoomed into, so the same chart always reads the same way, and the distance labels gain decimals as the ticks come closer together. Shift-dragging across the plot (or a long press then a drag, on a touch screen) marks out a **stretch** of the profile: it is banded in the chart, highlighted on the map, and the footer swaps the whole line's climb totals for that stretch's own figures — its length, its climb and descent, the elevations it runs between, and its end-to-end steepness. Either edge can be dragged afterwards by the handle on it — the pointer says so as it passes over one — and dragging one past the other turns the stretch round; the × beside the figures clears it. A one-off toast names the chart's three gestures — zoom, slide, and mark out a stretch — worded for a mouse or for a touch screen depending on which the device has, with the usual "Don't show next time". It rides in the URL as `elevation-chart-range=<from>,<to>` (metres along the profile), so a marked stretch can be linked to. Clicking a place in the chart brings it out on the map: unless it is already well in view, the map moves so the place sits in the middle of its largest part that nothing covers, since the panel is usually over what it points at. A toolbar below the chart can download it as SVG (not in an embedded map, where the browser forbids downloads), open the elevation preferences, put the panel full screen, and, when the line carries waypoints, toggle their markers and labels; the grips at its corners move and resize the chart window, and both the size and the position are remembered for the next time it opens. Under the toolbar the chart credits the terrain models its elevation was actually read from, as the elevation API reports them: the national high-resolution ones (premium) plus GEDTM30 past their borders, or SRTM. A dataset that credits several agencies at once can run to a dozen or more entries; past two the footer writes none of them out and instead shows the label with their count, which opens the whole list in a toast — the elevation readout's ⓘ does the same. A route on the free tier keeps the router's own elevation instead, which is credited to Sonny's LiDAR DTM. Non-premium users get a premium gem there offering higher-precision data. Elevation the user recorded or imported is credited to nobody, so the line is omitted for live tracking and for tracks shown as recorded.

Only one profile is shown at a time, and it stays with whatever opened it — a planned route, an imported track, a tracked device or a drawn line — redrawing itself as that line changes (re-routing, reshaping a drawn line, live positions arriving) rather than closing. Closing the tool it was opened from does not close it either: the line stays on the map, so the profile stays with it, and it can be linked to without any tool open. It goes when its own × is pressed, when the map is cleared, or when the line it charts is deleted. Which one it is shows in the URL as `elevation-chart=` (see "Deep links" in [llms.txt](/llms.txt)), so a link can share an opened profile.
