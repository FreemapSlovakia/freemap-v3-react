## Manage maps

- Access: Manage maps button (the gear in the map toolbar, see [Map Layers](/llms-layers.md))

A menu of five items in three groups: **Map manager**, the modal whose two tabs are **Installed maps**, where each map the user has is configured, and **Available maps**, where more maps are found and installed, with **New custom map** in its footer (see **Custom maps**); then the two that keep copies of maps, **Offline maps** (suffixed with the total cache size) and **Caching while browsing**; then **Map preferences** and **Elevation preferences**.

### Installed maps and Available maps

- Keyboard shortcut: <kbd>m</kbd> <kbd>m</kbd> (Installed maps), <kbd>m</kbd> <kbd>a</kbd> (Available maps)
- URL path: `/#show=installed-maps` and `/#show=available-maps` (the older `/#show=map-library`, `/#show=map-layers-config` and `/#show=map-settings` open Installed maps)

The maps on offer are the built-in ones and about 600 more — orthophotos, historic imagery and maps, elevation and other tile maps from around the world — taken from the OSM Editor Layer Index (credited at the bottom of Available maps, CC BY-SA 3.0), plus hand-picked Slovak maps and overlays named in Slovak: the base map series and administrative map (GKÚ), the forest stand map (NLC), the water management map (VÚVH), landslides (ŠGÚDŠ), protected areas and Natura 2000 (ŠOP SR), the Q100 flood hazard (SVP), heritage areas (PÚ SR) and the railway network (ŽSR). Those are not installed until the user adds them; a link to one (`layers=<5-character id>~`) shows it all the same.

The modal's two tabs, **Installed maps (N)** and **Available maps (N)**, switch between the two, each with its own box and filter chips; a group of chips lets everything through until one of its chips is on, and then shows what matches any of them.

**Installed maps** has a "Filter installed maps" box (by name) and chips for **Category** (as in **Available maps**; a custom map has the one set in its form, an offline map its source map's, presets count as Other), **Technology** (Image tiles, Vector, WMS, Parametric shading, Color, Data layers — the overlays the app draws itself: photos, map features, Wikipedia, viewshed, weather radar), **Country** (a dropdown of the countries the maps name, with flags, one at a time; beside it **Include multi-country maps**, on by default, keeps the maps without a country list of their own — worldwide ones, the Europe-wide outdoor-map family, or the user's own — while one is picked; off, only the country's own datasets remain), **Layer** (Base maps, Overlays), **Kind** (Built-in, From the library, Custom, Offline, Presets), **Shown** (In toolbar, In menu, Hidden — in neither the toolbar nor the menu, With shortcut) and **Covers this view** (as in **Available maps**; an offline map covers its downloaded area). It lists the installed library maps, every custom map and offline map, and the map presets (see **Map presets**) in one table: the base maps first, then the overlays, presets first in each; every map shows under its name its kind (Built-in, From the library, Custom, Offline, Preset), category (unless Other) and technology, each with its filter chip's icon (on a narrow screen the icons alone, the words on long press), an offline map its source map's category and the map it was downloaded from, a preset its bottom layer and how many more it holds; **Available maps** rows show the same category and technology. A table shows every map's settings at once, in columns: show in toolbar, show in menu, base map / overlay (the **Base / Overlay** switch for a map whose kind can switch, see below; otherwise its mark, a preset's by whether it holds a base map), opacity (every map and preset, base maps too, which then show the map background through; the same opacity the Map layers panel sets; not on a narrow screen) and a keyboard shortcut (a 🚫 marker indicates that no shortcut can be assigned); then a ⋮ menu with the row's actions: **Preview on the map** (all but presets, see below), **Show on map** (presets), **Modify** (custom maps and presets open their form, see **Custom maps**; an offline map opens its form in **Offline maps**), **Download for offline use** (image-tile library and custom maps: opens the **Offline maps** download form with the map already picked), and **Uninstall** (library maps) or **Delete**, after asking (custom maps and presets). Overlays are listed as they stack on the map, top first, as the map menu and toolbar list them; the order is set by dragging in the Map layers panel. Every setting takes effect at once, with no Save; **Reset to default** puts every map's settings and layer setup (opacity, kind, WMS layers, shading, colour) back after asking, leaving what is installed alone. **New custom map** in the footer opens an empty form.

**Available maps** lists only what can still be added — an installed map is under **Installed maps**, and each tab shows its count. It searches them ("Search N maps") — by name, by country (code or name) and by the same keywords the search box knows — and lists the matches best first, in one table whose rows start with the base map / overlay icon; when nothing matches it says so, and when the search matches no map at all, installed ones included, it asks the user to suggest the missing map at freemap@freemap.sk; with the box empty it lists the whole catalog: the maps that draw in the current view first, within each part base maps before overlays, each sorted by name. More rows load as the list is scrolled to its end. Its chips are **Category** (Maps, Historic maps, Orthophotos, Historic imagery, Elevation, Other), **Technology** and **Country** as above, **Layer** (Base maps, Overlays) and **Covers this view**, which keeps the maps that draw where the map is (judged by the countries in view and, outside Europe or at sea, by each map's bounding box alone, which is coarse). Each result has a **+** that installs it at once, moving it to **Installed maps**. Every map but a preset, in either list, has an eye button that previews it: the modal steps aside, the map is switched on and, if the view is away from it, the view moves to it. The map can be panned and zoomed, but the rest of the interface is put away as while picking a place, and maps can't be switched. A toolbar then offers **Install** (for a map not installed), **Keep on map** (leaves it on and closes the modal — a map can be used this way without installing it), **Back to library** (<kbd>Esc</kbd>) and **×**; the last two put back the layers that were on before. An uninstalled map is left out of the toolbar, the menu (even under **Show all**), its keyboard shortcut, the search box, **Installed maps** and the offline-map and export pickers, while a link naming it in `layers=` still shows it and the menu lists it for as long as it is on. Built-in maps are installed by default, except the third-party Public transport (ÖPNV) and the four MapTiler vector maps (OpenStreetMap, Streets, Dataviz and Outdoor Vector), which are added from **Available maps**, and on freemap.eu the maps covering only Slovakia; such a map counts as installed once any of its settings is set.

### Custom maps

- Access: **New custom map** in the footer of Installed maps or Available maps (Manage maps button > Map manager), or **Modify** in a custom map's ⋮ menu in **Installed maps**
- URL path: none of its own; the older `/#show=custom-maps` opens Installed maps, which lists them

The form for a user-defined map layer, shown in place of the modal's list; Save returns to **Installed maps** (see below); Cancel returns to the tab the form was opened from, keeping its search, or closes it when opened from the menu. Each custom map has:

- name
- icon, picked from the same icon set the drawing points use (Font Awesome and the OSM POI icons); the map type's icon is used when none is picked
- type (technology): Image tiles (TMS, XYZ), Vector (MapLibre) or WMS
- category, as Installed maps and Available maps filter by (Maps, Historic maps, Orthophotos, Historic imagery, Elevation, Other)
- URL (tile template for TMS/XYZ, server URL for WMS, or style URL for MapLibre)
- for WMS: the service's layers drawn by default, as a tree like the Map layers panel's (below); what is ticked in the panel replaces them until the row's **Reset to default**, and saving the form goes back to them
- min zoom / max native zoom (for a WMS the latter caps the requested image resolution instead of the zoom drawn at)
- extra resolutions and "scale with DPI" (not for WMS, which always matches the display density)
- for WMS: "load in tiles" — off by default, since a WMS is asked for one GetMap covering the whole view per pan/zoom; switch it on for a server that limits image size or caches tiles
- layer: base or overlay, the map's default kind (an overlay is always drawn above the base map; where it stacks among the overlays is set by dragging in the Map layers panel); the map can be switched to the other kind on the map, as a library map can, and saving the form goes back to this one
- show in toolbar / show in menu, and a keyboard shortcut (on devices with a keyboard); opacity is set in **Installed maps** or the Map layers panel

Saving goes back to **Installed maps** with the saved map scrolled into view and briefly highlighted.

Terrain shading and a plain colour are not custom maps: the built-in **Parametric terrain shading** (`h`) and **Solid colour** (`c`) maps are set up in the Map layers panel, and a setup worth keeping under a name is saved as a named map (see **Named maps**). Solid colour is one colour all over — a blank base map to lay overlays on, or a tint as an overlay — and needs no network; it is installed but left out of the menu by default.

Any library or custom map but the data layers — WMS, shading, solid colour, raster tile or vector (MapLibre) — can be used as either a base map or an overlay: the **Base / Overlay** switch in its row of Installed maps or of the Map layers panel (below). A WMS base map used as an overlay is asked for transparent images, so it shows only what it draws (shading covers what is beneath only where it has a background colour); a raster tile or vector base map, or the solid colour, is opaque, so as an overlay it covers the map beneath until its opacity is lowered, and then blends with it — e.g. aerial imagery over Outdoor, or an old map over a new one (the switch never changes a map's opacity); a vector overlay such as Forest tracks NLC can be a base map over the map background. The data layers (photos, Wikipedia, weather radar, …) keep their kind. With no base map on, the map background (see Map preferences) shows beneath; one switched to a base map replaces the base map that is on. Offline maps keep the kind they were downloaded with.

### Layer setups

Each map keeps **one setup** of its own: its opacity, base/overlay kind, ticked WMS layers, shading or colour — whatever its page in the Map layers panel sets. The setup is kept for the account (in the browser when signed out) whether the map is on or off, so a map turned off and on again comes back as it was left. **Reset to default** on the page puts that map back to its defaults. A map's WMS layers, shading and colour are its own wherever it is drawn: changed inside a map preset, they change on its own and in every other preset too. Only its opacity and base/overlay kind are kept per preset (see **Map presets**). A link carries the setup of every layer on the map, presets included, so it reproduces what is on screen (see "Deep links" in [llms.txt](/llms.txt)), and opening it loads those setups; a My maps document stores them the same way.

### Map layers panel

The **Map layers** button beside the map switcher in the map toolbar opens a panel listing what is on the map, top first: the overlays and overlay presets in their stacking order, then the base map (or the preset holding it). Its open state is remembered, and turning on a WMS or shading map opens it at that map's settings. Each overlay row has a drag handle that moves it up or down the stack (the photo, Wikipedia and OSM data layers always draw on top, so they have none), every row a base/overlay mark — a button opening the **Base / Overlay** switch for a map that can be either — and an opacity swatch that opens a slider — a faded base map shows the map background through; every row, the base map's too, has **Remove**, which takes it off the map — without a base map the map background (see Map preferences) shows, and a link or a reload keeps it so. An overlay turned on goes to its default place among those on. **Save layers as preset** at the bottom makes a preset of the maps on the map (see **Map presets**); it is shown where there are two maps or presets or more to combine, or one map at an opacity or kind other than its defaults (its WMS layers or shading stay the map's; **Save as map** keeps those under a name) — not for a lone preset, which would come out a copy of itself; while photos, Wikipedia, the weather radar or the viewshed is on, which a preset can't hold, it is disabled and its tooltip names the layers to turn off.

The panel drills down rather than expanding rows, so a map's settings are shown with no other layer beside them, and **←** in the header goes back up. A row's name opens a page only where there is more to set than its kind and opacity — a WMS, shading, Solid colour, custom or named map, and a preset. Such a map opens to a page of its setup (see **Layer setups**):

- its opacity (a base map's too)
- the **Base / Overlay** switch, for any library or custom map but the data layers
- for a WMS map, the service's layers (below)
- for the shading layer, the shading editor (below)
- for Solid colour, its colour (with alpha while it is an overlay)
- for a WMS, shading or Solid colour map, **Save as map**, which keeps it as set up under a name (see **Named maps**)
- for a custom or named map, **Modify**, which opens its form
- **Reset to default**, which puts that setup back to the map's defaults

A preset opens to its own layers, listed the same way: each with its opacity, a drag handle among the preset's overlays, **Remove** (takes it out of the preset) and its own page of settings; above them the preset's own opacity, and below them **Add map**, which adds an installed map to the preset — a base map in place of the preset's own. Offline maps and the data layers can't be in a preset; deleting a custom or offline map takes it out of the presets holding it.

A WMS map's row lists the service's layers as a tree; ticking one draws it at once. **Select all** and **Deselect all** act on every layer shown, and a service with more than ten layers gets a search box that narrows the tree (and what those two buttons act on). The custom map form's layer list works the same way.

At the top of the shading row, **On server** / **In browser** chooses where shading is rendered; the choice is remembered, and **On server** is the default. In the browser (experimental; WebGPU, disabled without it) edits show as they are made. On the server tiles arrive as finished WebP images: edits show only after **Apply**, and **Revert** drops them — both stay in place, disabled while there is nothing to apply. Edits not applied yet are kept for the session when the page is left, and the map's row in the panel carries a warning triangle until they are applied or reverted.

The row lists the shading's layers (hillshade, slope, colour relief, aspect, and a background), with **Add** and **Remove**. Without a background, what is beneath shows through, so shading can be a base map or an overlay. A **Presets** button beside them replaces the whole shading with a ready-made one — cartographic (Classic, Freemap outdoor, Shadow only, Multidirectional, Embossed, Swiss style, Steepness, Hypsometric tints + shading, Aspect + slope, Contour, Fog / inversion) or artistic, listed alphabetically (Autumn, Blueprint, Glacier, Golden hour, Ink drawing, Mars, Metallic, Moonlight, Neon, Night, Sepia, Watercolour), each marked as opaque (with a background) or as an overlay — asking first when the shading is not already a preset. It applies at once, without **Apply**. **With background** below it (ticked by default while the shading is a base map, so the map background doesn't show through) decides the background: ticked, an overlay preset gets a white one and every preset is marked opaque; unticked, the presets whose background is only paper under them (Embossed, Swiss style, Glacier, Golden hour, Ink drawing, Watercolour) leave it out and work as overlays too. With **Add to existing** ticked at the top of the menu, an overlay preset's layers are added to the shading instead (the opaque presets are disabled then), as an edit like **Add**. Some presets ask for values first: Contour and Fog / inversion an elevation and band width with their colours, Hypsometric tints the elevations of the bottom and top colours, Metallic the number of repeats (1–7) and its highlight and shadow colours, whose pickers offer metal tones (the highlight also fills the background). A dial sets the light's azimuth and elevation for the hillshade and slope layers by dragging their handles. Below it, a collapsed **Parameters** section holds the selected layer's azimuth and elevation as numbers, and its **Height exaggeration**, **Contrast** and **Brightness** as sliders with a typed value beside each; the typed value can go past the slider's range. Contrast and brightness go into the link only when they differ from 1 and 0.

### Named maps

A **named map** is a WMS map (a library one or one of the user's own servers), the shading or Solid colour, kept as set up under a name and icon of its own — e.g. "Parcels" (the cadastre with only the parcel layers ticked) or "Contour 1000". **Save as map** on the map's page in the Map layers panel creates it from how the map is drawn there, kind included, and puts it in that map's place, on the map or inside a preset. It is a map like any other: in Installed maps, the menu, the toolbar, with a shortcut, and inside presets under its own name. Its WMS layers, shading or colour are edited on its page in the Map layers panel, and a change shows wherever it is used; **Modify** in Installed maps edits its name, icon and how it is reached, and **Delete** removes it from the map and from every preset. Deleting a custom WMS map deletes the named maps built on it; the confirmation names them.

### Map presets

A **map preset** is a named layer made of maps, bottom first, each at its own opacity and kind — e.g. aerial imagery under a half-transparent "Parcels". On the map it is one layer: switched on and off like a map, from the map menu (among the base maps with a radio for one with a base map, sorted by name with the custom maps; among the overlays with a checkbox for one without, in its stacking place), its toolbar button (overlays' buttons, presets' too, have a coloured top-left corner), its keyboard shortcut, the search box or **Show on map** in Installed maps. One with a base map takes the base map's place, and picking a base map takes it off with all its layers; one without stacks among the overlays, any number at once. Either has an opacity of its own that fades it as one picture. A map turned on beside a preset is a layer of its own, even when the preset holds the same map — both are drawn, each at its own opacity and kind, and the map's toolbar button shows only the map's own.

**Save layers as preset** in the Map layers panel makes a preset of copies of the maps on the map, presets taken apart, in their place — a map drawn twice (on its own and in a preset, or in two presets) becomes one, at the upper drawing's opacity; **Duplicate** inside a preset makes a copy of it in its place, to change without touching the original. The form asks only for a name, an icon and how it is reached (toolbar, menu, shortcut); **Modify** in Installed maps edits the same. Its layers are edited on the map, inside the preset in the Map layers panel, and every change is kept at once. A preset never contains another preset, nor the photo, Wikipedia, OSM data, weather radar or viewshed layers.

A link or a My maps document carries the presets on the map as copies, so it opens the same for anyone. Opened by the account that made it, a copy the same as one of its presets turns that preset on; any other is a preset of the link's own, which the Map layers panel offers to **Save as preset**.

### Map preferences

- Keyboard shortcut: <kbd>m</kbd> <kbd>p</kbd>
- URL path: `/#show=map-preferences`

- **Max zoom** — global maximum zoom level
- **Zoom step** — the smallest zoom change scroll-wheel, pinch, box zoom and the one-finger double-tap drag can settle on: `1` (whole zoom levels, the default), `½`, `¼`, or *Free* (no snapping at all). The <kbd>+</kbd>/<kbd>−</kbd> buttons and keys always go to the next whole level whatever this says
- **Resolution scale** — simulates display pixel density and affects which tile variant is fetched (Auto by default)
- **Feature size** — enlarges rendered labels and lines (no effect on satellite, shading, WMS, or vector (MapLibre) layers)
- **Map background** — the colour wherever no layer draws: with no base map on, beside a base map with partial coverage or transparency, and under tiles still loading (Leaflet's grey by default); with **Checkerboard** (on by default) it is drawn as a checkerboard of that colour, so transparency shows; this browser's own
- **Direction indicator** — source of the direction beam on the located position: *Hidden*, *Direction of travel* (GPS course over ground, visible only while moving) or *Device compass* (magnetometer, works standing still, offered only where orientation sensors exist). Defaults to the compass except on iOS, where enabling it costs a permission prompt, so direction of travel is the default there
- **Distance and bearing** — while locating, draws a line between the located position and a crosshair in the middle of the map, labelled with the distance and the bearing from the position to the crosshair; visible only once the map is panned away from that position. On by default
- **Reset to default** — fills this modal's fields (max zoom, zoom step, resolution scale, feature size, map background, direction indicator, distance and bearing) with their defaults; apply with Save or close without saving

### Elevation preferences

- Access: Manage maps button > Elevation preferences, or the gear in the elevation profile's toolbar
- Keyboard shortcut: <kbd>m</kbd> <kbd>e</kbd>
- URL path: `/#show=elevation-settings`

- **Remove spikes** — a slider, 0–100 m, default 25 m. Where a way is drawn a few metres off the road it describes, the terrain model answers with the bank or rock face beside it; a running median drops excursions narrower than half this window, up or down, and keeps anything wider as real terrain, followed by a light average that rounds off the steps a median leaves. Zero switches it off
- **Fill terrain-model ditches** — a slider, 0–100 m, default 25 m. The detailed national terrain models (available in some countries) are usually adjusted for hydrology and dig a ditch through the road at every culvert; dips narrower than this are filled in the elevation profile and its climb/descent totals, while wider ones are kept as real terrain. Zero switches it off, and it changes nothing where the global model is used. Bridges and tunnels a route crosses are levelled separately, from the router's own data, and are unaffected by this setting
- **Steepness window** — a slider, 0–200 m plus a final "whole line" notch, default 50 m. The steepness reported at the place pointed at on the elevation profile is averaged over a stretch this long around it, so a couple of metres of GPS noise don't read as a wall. The window is centred on that place itself, so on a track whose points are far apart it still describes the stretch under the pointer rather than whatever surrounds the nearest point. Zero measures across just the segment the place stands on; "whole line" measures across the entire line at once, so the readout is the same everywhere on it and reports the rise over the line's whole length — on a straight measuring line that is the angle one end is seen at from the other, useful for sightlines (which ridge hides a summit or a sunset). Unlike the two sliders above it corrects nothing, so it changes no profile, only that readout

Which terrain model answers is not a setting: premium reads get the detailed national models where they exist and GEDTM30 past their borders, everyone else gets SRTM everywhere, for profiles and exports alike.

The first two sliders correct a terrain model, so they apply wherever elevation is read from one — planned routes, drawn lines and measurements, and imported tracks whose elevation was replaced from the server — and never to recorded altitude (live tracking, or a track kept as recorded).

Modals that edit a persisted default style or settings (Map preferences, Elevation preferences, drawing **Default properties**, objects **Marker style**, track-viewer **Default style**, **Lookup style**) also carry a **Reset to default** button that refills the form with default values (applied with Save, not immediately).
